KEY FILES EXPLAINED
===================

1. manage.py
   - Django's command-line utility
   - Used for: runserver, makemigrations, migrate, createsuperuser, etc.

2. settings.py
   - All project configuration
   - Database, apps, middleware, static files, email, etc.

3. urls.py (main)
   - Root URL configuration
   - Maps URLs to apps

4. models.py (in each app)
   - Database models (tables)
   - User, Crime, Evidence, Suspect, etc.

5. views.py (in each app)
   - Request handling logic
   - Processes forms, queries database, renders templates

6. forms.py (in each app)
   - Form definitions
   - Validation logic

7. templates/
   - HTML files
   - Rendered by views

8. static/
   - CSS, JavaScript, images
   - Served directly to browser

9. media/
   - User-uploaded files
   - Evidence, photos, documents


DATABASE MODELS
===============

User (accounts/models.py)
- Extends Django's AbstractUser
- Fields: username, email, role (CITIZEN/POLICE/ADMIN), phone, address, etc.

Crime (crimes/models.py)
- case_id, reporter, crime_type, title, description
- location, latitude, longitude
- status, priority, assigned_officer
- ai_predicted_category, ai_confidence

Evidence (crimes/models.py)
- crime (FK), evidence_type, file
- faces_detected, face_encodings

Suspect (crimes/models.py)
- crime (FK), name, description, photo
- face_encoding

CaseUpdate (crimes/models.py)
- crime (FK), old_status, new_status
- notes, updated_by


USER ROLES
==========

1. CITIZEN
   - Report crimes
   - Upload evidence
   - Track case status
   - View own reports

2. POLICE
   - View assigned cases
   - Update case status
   - Add suspects
   - Upload evidence
   - Access crime map & analytics

3. ADMIN
   - Full system access
   - Verify police officers
   - Assign cases
   - View all statistics
   - Manage users


WORKFLOWS
=========

1. Crime Reporting Flow
   Citizen → Register → Login → Report Crime → Upload Evidence → Track Status

2. Investigation Flow
   Police → Login → View Cases → Update Status → Add Suspects → Close Case

3. Admin Flow
   Admin → Login → Verify Police → View Analytics → Assign Cases


IMPORTANT DIRECTORIES
=====================

/migrations/
- Auto-generated database migration files
- Track database schema changes

/models/ (in ml_engine)
- Stores trained ML models
- crime_classifier.pkl, vectorizer.pkl
- Created when train_model() is run

/__pycache__/
- Python bytecode cache
- Auto-generated, can be deleted

/staticfiles/
- Collected static files for production
- Created by 'collectstatic' command


CONFIGURATION FILES
===================

.env
- Environment variables
- SECRET_KEY, database credentials, API keys
- NOT committed to Git (in .gitignore)

.env.example
- Template for .env
- Shows what variables are needed

.gitignore
- Files to exclude from Git
- .env, __pycache__, db.sqlite3, media/*, etc.

requirements.txt
- Python package dependencies
- Used by: pip install -r requirements.txt

TESTING
=======

Run tests:
    python manage.py test

Create test data:
    python manage.py shell
    (then create objects manually)


COMMON COMMANDS
===============

Start server:
    python manage.py runserver

Create migrations:
    python manage.py makemigrations

Apply migrations:
    python manage.py migrate

Create superuser:
    python manage.py createsuperuser

Collect static files:
    python manage.py collectstatic

Django shell:
    python manage.py shell

Database shell:
    python manage.py dbshell
